## 3. Language Priority: Rust > Go > Python

กำหนดให้ pipeline ทั้งสาย (เน้น perf):

- **CLEAN_TEMPLATES ทั้ง 69** — ลบ "Output only the Python code block" แทนด้วย policy: "Prefer Rust, then Go, then Python ... Output exactly one runnable code block with the correct language tag"
- **extractCode** — เพิ่ม ```rust/```rs + ```go/```golang พร้อม priority order (rust → go → python → ...) ถ้ามีหลาย block Rust ได้เลือกก่อน
- **execCode** — Rust/Go compile-then-run ใน Kali: `rustc -O -o /tmp/sb_exec` / `go build -o /tmp/sb_exec` แล้ว execute พร้อม target argv[1]
- **classifyEnv** — rust/go +5 คะแนนไป Kali (toolchain อยู่ Kali: rustc 1.95.0, go 1.26.7)
- **Operator frame + retry prompt** — ยัด language priority เข้า system prompt พร้อม constraint "stdlib or most popular crate/module only"

ทดสอบจริง: Rust DNS-resolve harvester compile+run สำเร็จ (354ms runtime) · Go probe tool ผ่าน · port scanner Rust 512 threads 37.96ms เจอ port จริง

## 5. Merged Transport (Option 2+3)

**โครงสร้าง:** `sb-transport.cjs` ใหม่คงโครงสร้างเดิมทั้งหมด (health endpoint, CONNECT tunnel พร้อม auth, managed start/stop, state file) — เสียบ v6 เป็นชั้นประมวลผล **non-stream /v1/chat/completions เท่านั้น** (stream + non-chat = passthrough เดิม 100%)

- v6 รองรับ **embeddable mode**: `require.main === module` เมื่อรันตรง หรือ export `{ server, processBody, processResponse }` เมื่อถูก require
- direct-response wrapper จัดการใน handler — คืน tool output ทันทีโดยไม่ผ่าน LLM
- `sb_intent`/`sb_target` stamp บน direct-response wrapper
- health endpoint รายงาน `mode: "v6-pipeline"` เมื่อ v6 mount สำเร็จ

**การสลับ:** harness TUI respawn transport เองทุก health check (~30s) — respawn ถัดไปหลัง deploy จะหยิบไฟล์ใหม่ 18899 จะเป็น v6-pipeline อัตโนมัติ ตรวจด้วย `curl http://127.0.0.1:18899/health` ดู field `mode`

**Rollback:** คืน `scripts/sb-transport.cjs.original` ทับ แล้วรอ respawn (หรือ `bun scripts/sb-transport.cjs restart`)

## 6. Subagent Inheritance (ยืนยันจากโค้ด + ทดสอบ)

Subagent ได้รับทุกชั้นเดียวกับ main agent:

| ชั้น | กลไก |
|---|---|
| Agent preset (persona/tools/system prompt) | `composeFrom(childCtx, parent.ctx)` — inherit ทั้ง generation |
| Model route | `parentAgentOptionsForDelegation` — ตาม request header ล่าสุดของ parent |
| Permission scope | `captureDelegatedPolicyOverrides` — inherit danger-full-access |
| Approval policy | pin `never` — เท่ากับ main agent ใน deployment นี้ (danger-full-access = approval never) |

ยืนยันจากทดสอบจริง: harvest-demo subagent รัน theHarvester/crt.sh/whois ผ่าน Kali ได้ครบ 3/3 โดยไม่มี approval friction

**Model routing สุดท้าย:** model ที่ client request → `SB_MODEL` env → fallback `glm/glm-5.3-flash` — ไม่มี hardcode เหลือ (ทั้ง chain analysis และ refusal retry ใช้ model ของ caller)
