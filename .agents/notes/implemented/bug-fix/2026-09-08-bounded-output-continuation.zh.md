# Agent Note: 有界输出续接

Status: implemented

[English](2026-09-08-bounded-output-continuation.md) | 中文

## Problem

本地模型可能在编码任务尚未完成时耗尽输出额度。输入压缩不能修复被截断的输出，而静默停止使这种失败难以与完成区分。

## Decision

[基础压缩插件](../../../../packages/compaction/compaction-basic/README.zh.md)在输入预算恢复之外提供可选的有界输出恢复。启用自动处理时，`maxOutputContinuations` 默认允许两个后续轮次。最近的请求必须以 `max-tokens` 结束；取消和已有输入优先。插件提示是持久化的模型可见消息。统计最近一条用户输入之后的这些消息，可避免压缩或恢复会话重新补充预算。

## Alternatives considered

**网关续接。** 网关不管理工具执行或客户端会话日志。在网关重发请求可能隐藏截断并破坏工具顺序。

**同一轮次内续接。** 循环在任何步骤被截断后都会保留 `max-tokens` 轮次结果。独立后续轮次既保留这一证据，又允许恢复后的响应正常完成。

**无限续接。** 反复仅输出推理可能在没有进展的情况下耗尽上下文。有限且可配置的额度限制自动成本。

## Consequences

现有压缩状态、输出上限提示和插件提示渲染器展示进度，无需新 UI 事件。截断的工具调用不会执行。token 上限不能证明任务在语义上尚未完成；续接提示明确允许在任务完成时给出简短最终答复。每次续接都会产生一次模型请求。显式摘要覆盖配置仍受支持；默认摘要模型跟随最近持久记录的提供方和模型路由。

## Verification

聚焦的真实循环测试覆盖正常完成、恢复、预算耗尽、新用户输入、取消、排队工作、禁用自动处理、插件卸载和截断工具调用。Loader 组合测试验证 YAML 设置和持久化续接。现有压缩测试覆盖路由模型选择及失败时保留历史。
