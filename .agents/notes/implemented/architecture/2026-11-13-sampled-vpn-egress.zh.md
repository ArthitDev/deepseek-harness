# Agent Note: 主机 VPN 出口采样

Status: implemented

[English](2026-11-13-sampled-vpn-egress.md) | 中文

## 问题

连接指示必须区分实际主机流量与已安装的隧道，也不能保留过期的成功结果。

## 决策

[主机 VPN 服务](../../../../packages/host/vpn-status/README.zh.md)通过真实 HTTPS 请求，使用 Mullvad 官方声明或运维人员配置的出口 IP/CIDR 进行验证。每个主机持有一个需主动启用的五分钟探测缓存；Web 和 TUI 读取该缓存并丢弃过期验证。[Web 状态贡献](../../../../packages/client/ui-vpn-status/README.zh.md)使用共享资源模型及可追加状态插槽，保留现有底部内容的注册。

## 理由

已安装的隧道适配器或 VPN 进程不能证明主机请求经过该路由，尤其是在分流和独立命名空间中。公共 IP 查询成功，若没有提供商证据或已知预期出口，仍不足以验证 VPN。界面显示主机 HTTPS 范围和上次检查时间，因为周期采样不能承诺持续保护，也不能覆盖其他目的地址、地址族、shell 或命名空间。默认禁用使第三方观测需要明确启用；开启检查会向 Mullvad 端点披露出口 IP。

## 考虑过的替代方案

**适配器和路由启发式检测**被拒绝，因为虚拟接口和操作系统路由查询可能显示隧道，但实际套接字不经该隧道传输。供应商专用 CLI 也会排除其他 VPN 产品和平台。

**仅检测公共 IP 变化**被拒绝，因为普通网络变化和代理也会改变公共 IP，无法证明 VPN 使用。预期出口支持多个提供商，同时由运维人员维护证据；它无法区分共享同一出口的其他路径。

**替换现有底部插槽**被拒绝，因为单占位扩展可能已拥有该插槽。可追加插槽保留该扩展，同时由状态条目负责自身展示。

## 影响

共享缓存限制外部请求次数，并保留现有底部贡献。采样放弃持续路由保证；其他提供商需要维护出口范围，且端点会观测公共出口 IP。

## 验证

聚焦测试覆盖外部 JSON、CIDR、HTTPS 来源和大小限制、缓存间隔、过期及清理。正式 Web 组合测试在恢复的真实录制会话旁，以明暗主题和窄宽视口呈现状态。Windows 和 Linux 服务命名空间的实时探测使用同一 Node HTTPS 实现；这些检查不会输出 IP 数据。
