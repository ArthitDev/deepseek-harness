# Agent Note: 按会话始终搜索 Web 模式

Status: implemented

[English](2026-09-09-always-web-search-mode.md) | 中文

## 问题

系统已有 web 工具，但用户无法持久表达“每个请求都要搜索”的偏好。在聊天中重复说明会随对话上下文变化而丢失，也没有可见的会话状态。

## 决策

`dsh-tool-web` 拥有从 `web-search/mode` 事件折叠出的 `webSearchMode` Session 投影。`/web-search always` 启用条件系统提示词区段，`/web-search auto` 将其关闭并把工具选择交给模型。常驻搜索指引仅针对最新或会变化的信息，或当上下文与模型的可靠知识不足时建议 `web_search`；其他情况保留直接回答或使用更相关工具的选择。搜索查询默认使用用户的语言，仅在能扩大覆盖范围时添加其他语言。Web bundle 挂载 `ui-web-search-mode`，在访问模式选择器旁的 `conversation.input.webSearch` 席位显示由宿主确认的 `Web Search` 开关。

该策略要求模型对每个用户请求执行一次外部 `web_search` 调用，在该调用中提交一至四条简洁查询，默认使用用户的语言，仅在用户要求时采用中文，引用返回来源，必要时使用 `web_fetch`，把 web 内容视为不可信数据，并在搜索失败后停止重试，而不是静默依赖记忆。该状态独立于权限、沙箱、审批与提供方配置。

## 持久化与提示词语义

事件日志是权威来源。投影重放会在刷新或恢复后还原模式，提示词组装会在每次请求时读取投影，包括压缩后的请求。生成的持久化目录包含 `web-search/mode`，因此采用失败时关闭策略的存储日志校验会在投影重放前识别该事件。默认非活动状态为 `{ always: false }`。

该模式会在每轮第一个模型步骤通过 scoped `agent/tool-choice` waterfall 返回提供方无关的 `toolChoice: 'required'`。DeepSeek 与 pi-ai adapter 把它映射到各自的提供方协议，而 system policy 负责指定 `web_search`。不具备可用结构化工具调用能力的模型或提供方仍无法可靠使用此模式。

## 考虑过的替代方案

**存储浏览器本地状态。** 放弃，因为它会与宿主漂移、跨浏览器丢失，也不能可靠影响提示词组装。

**加入适配器专用的强制工具选择。** 放弃，因为共享生成契约不支持它，而且与单一提供方耦合会产生不一致行为。

**把偏好写进每个 preset。** 放弃，因为用户需要独立于 preset 编写的单一会话控件，重复提示词也更容易失去同步。

## 后果

用户获得可见、持久的按会话控件及对应 slash command。切换模式会改变系统提示词前缀，因此也会改变 KV cache key。该功能不会绕过权限或网络限制：搜索仍要求已配置且可用的提供方；在适配器契约支持强制工具选择前，模型服从仍属于策略约束。
