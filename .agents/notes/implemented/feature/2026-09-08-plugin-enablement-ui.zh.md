# Agent Note: Confirmed plugin enablement editing

Status: implemented

[English](2026-09-08-plugin-enablement-ui.md) | 中文

## 问题

插件清单展示启停状态，但用户必须编辑 YAML 才能修改它。

## 决策

展开的卡片提供原生开关及明确的保存和取消操作。Host 解析配置路径，在文件锁内检查
文档的精确修订版本，并在持久化前保存同目录的 `.bak`。用户预设通过 roster 的写入
边界保存；全局工具和部署的 global-skills 钩子通过 profile patch 保存。基础设施、
内置预设、歧义条目、表达式和已禁用的祖先组受到保护。现有 Web 身份验证保持不变。

已挂载的清单在保存后立即刷新，并在每次读取完成一秒后再次读取。卸载时取消计时器
并忽略迟到的响应。轮询报告 Host 状态，不把持久化成功当作已经激活。

## 考虑过的替代方案

**直接修改 Loader：** 更改会在重启后丢失，并绕过配置源，因此改为持久化配置。

**允许切换所有全局插件：** 禁用网关或设置基础设施可能让恢复界面消失，因此这些
条目仍需通过配置管理。

## 后果

支持的开关不再需要用户编辑 YAML。预设序列化保留值和 `!!js`，但会丢弃注释。全局
patch 可能累积覆盖条目；现有重载策略和更高优先级的 patch 仍然适用。预设更改影响
新会话。保存成功并不保证运行时已激活。测试覆盖修订检查、备份、受保护条目、YAML
语义和确认流程。
